# 云枢 · 电商智能客服

> 一个把「客服」这件事**从一句问候做到数据闭环**的项目:流式对话 → 工具查数据 → 知识库检索 → 确定性编排 → 上下文管理 → 工具系统与 MCP → 观测与数据飞轮 → 微调主题分类器 → JWT 登录。
>
> 十章 + 一次功能追加,**每章都有自己的设计文档、开发留痕与端到端验收脚本**。

---

## 项目介绍

### 它解决什么

电商客服的真实问题不是「能不能聊」,而是这几件事同时成立:

- **答得准**:业务数据(订单/物流/商品)与政策文档(退换货、保修)都得查得到,查不到要**承认查不到**,而不是编一个;
- **记得住**:多轮对话里「那个订单」「退了吧」指的是什么,以及聊到第 50 轮时上下文还装得下;
- **改得动**:知识库能后台上传、能从真实会话里挖、能被人工审核回写;
- **看得见**:每一条回复走过了哪条链路、花了多少 token、哪一步没底气 —— 没底气的那些要**攒成数据**,而不是烂在日志里。

## 快速启动

### 前置

1. **Docker**(MySQL 8 跑在主机端口 **3307**,不是 3306;Milvus 由 `docker start milvus-standalone` 起)
2. **Python 3.13**
3. **一个 OpenAI 兼容的模型 key**(默认配的是 DeepSeek)
4. 首次冷启动会加载 **BGE-M3**(约 2.2GB)—— 第一次检索会明显慢,那是预热,不是卡死

### 五步

```bash
# 1. 依赖
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt

# 2. 配置:填 OPENAI_BASE_URL / OPENAI_API_KEY / OPENAI_MODEL 三项(其余都有默认值)
cp .env.example .env

# 3. 起依赖(MySQL 与 Milvus)
docker start mysql milvus-standalone

# 4. 建表 + 建知识库 + 预置账号(三步都幂等)
.venv/Scripts/python.exe scripts/init_db.py
.venv/Scripts/python.exe scripts/build_kb.py
.venv/Scripts/python.exe scripts/seed_users.py

# 5. 起服务
.venv/Scripts/python.exe -m uvicorn app.main:app --port 8000
```

> ⚠️ **`init_db.py` 永不加列**:它只建**不存在的表**。所以升级一个老库时,还要按顺序补跑
> `db/ch03.sql` → `ch04` → `ch06` → `ch07` → `ch08`(每份都**刻意不幂等**,重复执行会响亮地报错)。
> 四份不带章号的特殊产物(`db/ch09.sql` / `db/ch10.sql` / `db/auth.sql` /
> `db/followup_messages_citations.sql`)各有自己的走法,写在它们各自的文件头与 `CLAUDE.md` 里。

### 可选:另起两个进程

```bash
.venv/Scripts/python.exe -m mcp_servers.logistics     # 物流工具,8101
.venv/Scripts/python.exe -m mcp_servers.aftersales    # 售后工具,8102
.venv/Scripts/python.exe -m topic_service --model models/topic-clf --port 8103
```

> ⚠️ 三个都**不是必需**的:两个 MCP Server 起不来时聊天会**降级**(少几个工具,不报错);
> 分类器是旁路。`models/topic-clf` 有 409MB,**不入库** ⇒ 换台机器要重训(`scripts/train_topic_clf.py`)。

### 四个会绊一下人的地方

- **必须用 Git Bash 跑脚本**,不是 WSL 的 bash(从 Python/`cmd` 里调 `bash` 会解析到 WSL,而那里 `localhost` 与 `/tmp` 都不是 Windows 这边的);
- **静态页没有缓存头** ⇒ 改了前端要 **Ctrl+F5**;
- **含中文的请求体别走 `curl` 的 argv**(会被按 cp936 重编码)—— 走 stdin heredoc 或 httpx;
- **起服务前先清 8000 的残留进程**,否则会 curl 到旧代码,得到一类「新代码坏了」的假红。

## 项目亮点

### 1. 确定性骨架,ReAct 只是其中的一个节点

`resolve_references → classify_intent → route_by_intent` 是**纯函数,写死在代码里** —— 模型只负责给出**意图标签**,不决定走向。知识类走「强制预检索 + 置信度闸」再进 Agent;业务类直交 Agent;退款/售后走一条**独立的确定性子流程**(取订单 → 扩写 + 强制检索政策 → 判「这一单能不能退」→ 给退款表单或说明原因)。

> 唯一一处例外(「转人工」发生后取决于模型记不记得调工具)**如实记账在 spec 与 dev-notes 里**,并被验收脚本测成一个**比例读数**,而不是假装它也是结构保证。

### 2. 三层上下文,预算从模型窗口倒推

```
messages 表(按 id 升序)
├──────────────┬─────────────────────┬────────────────────┐
│  已被梗概覆盖 │   层 2:截短,30%     │   层 1:原文,70%     │
└──────────────┴─────────────────────┴────────────────────┘
                ▲                     ▲
      summary_upto_msg_id     layer1_from_msg_id   ← 都是 messages.id
```

- 预算**从模型窗口倒推**(`memory/budget.py`),不写死常量;
- **降级只挪 id、不搬数据** —— 超预算就把锚点往后挪,挪过的轮次自动落进层 2;
- **三个动作看的版本不同**:降级看层 1 原文、摘要看层 2 截短后、而摘要**读的是原文**(拿截短文本去提炼 = 把截断损失焊进梗概);
- 「落库 + 推锚点」是**一个原子动作** —— 只成一半会**静默**地让一段历史永久消失。

### 3. 工具系统的接缝:内置与 MCP 在注册表里长得一模一样

工具被描述成 `ToolSpec`(名字 / 用途 / **原始 JSON Schema** / `read`|`write` / 来源)进注册中心;**在 `app/tools/builtin/` 加一个文件就是一个新工具**(自动发现);全仓**唯一**的 JSON Schema 校验器与**唯一**的执行点;`app/tools/` 里**没有一行**知道手里这条工具是从哪来的 —— 想加 MCP,改的是 `app/mcp/client.py`,不是执行器。

写操作走**三态确认流**:Agent 撞到未确认的写调用就**停循环** → `interrupt()` 弹卡片 → 用户点选后同 thread 续跑 → 执行或拒绝,**而挂起的那一轮完全不落库**。

### 4. 观测 + 数据飞轮:把「答不上来」变成资产

- **观测**:每请求一个根观测 + 一个检索 span + 意图 tag;三个 `LANGFUSE_*` 任一为空 ⇒ 整套观测 no-op **且不 import langfuse**(「全程不联网」由一条源码扫描测试守着)。
- **飞轮**:低置信度池有**三个入口**(置信度闸 / 生成自评 / 用户点 👎),每行带**当轮召回快照**;`normalize → dedupe → pipeline` 做语义查重归并 → 人工**待审**;**通过即写知识库并同步向量化** —— 所以「同一个问题再问就答对」不必等下一次重建索引。
- 每轮评估落 `eval_runs`,趋势表把「这一轮比上一轮」的增减标出来;条数不同的两轮**整行不打箭头**(比的是同一件事才算变化)。

### 5. 微调 17 类多标签主题分类器,把「该补哪块知识」变成一个能算的数

RoBERTa-wwm-ext **全参微调**(不是 LoRA),配语料合流 / 配额合成 / 大模型预标 / 分层切分;**旁路推理服务**(独立进程,不在对话链路上)按批跑,结果写 `topic_classifications`,工作台「主题分布」页读它。

> **五条命门**里最典型的一条:**标签顺序是契约** —— 模型第 N 个 logit 对应哪个类目,靠**产物里那张表的下标**;服务若自己硬编码一份顺序,**分布图会整张错位,而每一个组件都工作正常**。所以三道防线全落在产物上,服务与评测只走同一个读侧,`/healthz` 把整张标签表印出来。

### 6. 认证:权限矩阵由测试**逐行**钉死

不只是「加了个登录」:27 个操作按 spec 一张表分给 `require_user` / `require_admin`,而 `tests/test_auth_wiring.py` **把那张表整张抄进断言**(集合 + **每一行挂的是哪一个守卫**)。

> 这条测试的存在理由值得说:测试里有一个全局装置给每条用例默认注入一个已登录管理员 —— 它让「这个端点受不受保护」变得**恒真**。所以必须另有一条**不经过那个装置**的断言兜住它。写这条断言时实测到一个坑:FastAPI 0.141 的 `include_router` 往 `app.routes` 里放的是**包装对象**而不是 `APIRoute`,朴素写法**一条都遍历不到** —— 那条防假绿的测试**自己就会是假的**。

### 7. 每个数都能追到一份产物

项目对「看起来对了」有近乎偏执的防备,并且**把这些防备写进了仓库**:

- **7 个端到端验收脚本**跑的是确定性的东西(帧名、日志行、由生产代码现算的预算数字),不靠模型自由文本;
- **变异探针**:改坏一处实现,断言**必须**红,而且探针要报出**红在哪一条**(红在无关用例上等于零判别力);
- `docs/superpowers/specs/` 是**设计源**(含「实现订正」小节:代码与最初设计的偏离及原因);`dev-notes/chNN.md` 是按阶段实时留痕(含翻车与返工);
- 一个数字写进文档之前先找到它的产物 —— 找不到就标注**未验证**,而不是让它读起来像读数。
