| 任务 | 产出 | 测试 |
|---|---|---|
| T7 | `app/kb/writer.py`(`vector_text` / `write_chunks` / `vectorize_rows` / `vectorize_pending`) | 单测 7 条 + db 5 条,全绿 |

- **时序**(spec §6.2):`INSERT (pending)` → 嵌入 → `Milvus upsert(同 pk 覆盖)` → `UPDATE vector_id + status=done`。`vectorize_rows` **先写 Milvus、成功了才改状态并提交** —— 反过来的话写 Milvus 失败的行会被记成 done、重跑再也不补,是静默的永久缺失(有专门一条单测钉这个顺序)。
- **幂等两处**:①`write_chunks` 按 `(category, questions, answer)` 三元组对库查重 → 重复导入 = 无操作,已 done 的行不被打回 pending;②`vectorize_pending` 每批一次 encode + 一次批量 upsert + 一次提交,中断后重跑重扫 pending,同 pk 覆盖。
- **中断重跑实测**(真 MySQL,store 为替身):写第 3 行时抛错 → 前 2 行 done、后 2 行 pending → 重跑(新 session)→ pending 清零、`vector_id == str(id)`,且两次运行合计**每个 pk 恰 upsert 一次**(计数器在 upsert 边界)。
- 顺带实现 `prev_chunk_id`/`next_chunk_id`(用户需求里的「前后块指针」元数据):同 section 的相邻新块双向串联,跨 section 不串。

### ④ 翻车与返工
