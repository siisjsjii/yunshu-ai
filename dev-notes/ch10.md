### 阶段 0 续:分节设计(逐节点头)

- **§0 总体架构** —— 用户回「对」。两条支线(A 支转人工第九类先做,B 支主题分类器);
  落点照仓库既有形状(`app/topic/` 纯数据 + `topic_service/` 旁路进程 + `scripts/` 五个入口);
  **两条不变量**:① 实时对话主链路零调用(源码扫描测试守着,照 ch09 那条 langfuse 边界的先例);
  ② 17 类表唯一来源(预标/合成/训练/评测/页面全部 import 同一个 `taxonomy.py`)。
  权重放 `models/topic-clf/` 并 gitignore,**可复现性靠脚本 + 冻结测试集,不靠权重入库**。
- **方案 A 获批**:配额造 + 形态强制 + 双池分离(合成 ≥30% 多标签、≥15% 近邻边界对、
  **禁止出现类目名与边界说明原词**)。
- **§1 数据处理四步** —— 用户回「对」+ 单独点了错别字那一项。
  **纠偏(我提的,用户接受)**:需求原文「清洗:脱敏、**修错别字**和格式」里的**修错别字被拿掉** ——
  改成「保留错别字 + 在增强阶段主动注入」。三条理由:① 改干净 = 训练/部署不一致,且**测试集也修过
  ⇒ F1 虚高且测不出**这个下降;② 修正本身引幻觉且静默污染全部数据;③ 注入只扩训练集、方向正确。
  另立一条**无论改不改都要有的规矩**:清洗函数**训练侧与推理侧同源**(`clean.py` 一处实现),
  写成测试守着,防 train/serve skew。
  **测试集规模问题已当面提出**:120 条 ÷ 17 类 ≈ 每类 7 条,F1 一条判错掉 0.14 ⇒
  建议头四类每类 ≥15 条,并在评测节写明「哪些类的 F1 不许单独引用」。
  **17 类里没有「投诉」「闲聊」「转人工」** —— 9→17 映射表里只能落「其他」,要在表里明说。

- **§2 标注** —— 用户回「对」。
  口径钉死为「**字面**提到」而非「意图」,配 5 条照见边界的例子(买大了想退 / 退货运费谁承担 /
  保修期内坏了能退吗 / 满多少钱包邮 / 我要转人工 → `其他`)。
  **新增的结构保证:预标必须带「证据串」**,且**证据必须是原文子串** —— 不做这步,「字面提到」
  只是 prompt 里一句话、没有任何东西在守。证据串顺带进 `topic_classifications` 与分布页悬停。
  **人工抽审 = 测错误率,不是逐条改**(训练/验证按类各抽 5 条 = 85 条;>10% 不训练先修 prompt)。
  **训练集标签错误率是本章 F1 的已知上界**,必须与 F1 并排写进报告。
  新增两条直译需求原话的指标:**标签数完全一致率** + **整条完全一致率(subset accuracy)**。
  「其他」类在合成里要留配额。
- **§3 训练** —— 用户回「对」。查证结论(本机 5.17.0 源码 + 官方 `MIGRATION_GUIDE_V5.md`):
  **① `problem_type` 是从 `labels.dtype` 猜出来的**(`loss/loss_utils.py:94-118` 原文),
  整数标签会被静默判成单标签交叉熵,且**第一个 batch 上定下来就锁死** ⇒
  显式传 `problem_type="multi_label_classification"` + 断言 float 标签 + 一条 loss 单测。
  属本仓「静默无效」家族第四个成员。**② v5 改名**:`processing_class=`(非 `tokenizer=`)、
  `eval_strategy=`(非 `evaluation_strategy=`)、`use_fast` 被无条件丢弃。
  **③ `max_length=64` 有实测依据**(问题中位 16 字 / 最长 31 字 / ≥48 字 0 条)。
  **④ 早停盯 micro-F1 不盯 macro-F1** —— 验证集每类仅 7 条,拿 macro 早停是让噪声决定。
  **⑤ 不用 `pos_weight`**:它改概率尺度,阈值与页面置信度就不再是概率;不平衡交给配额造数据。
  **⑥ 阈值只扫全局单阈值(0.3–0.7),不做每类阈值**(每类 7 条上调每类 = 调噪声)。
  **⑦ `load_best_model_at_end=True` 要求 `save_strategy == eval_strategy`**,提前钉住以免返工。
  产物 `models/topic-clf/`,meta 里必须有**数据指纹**。
- **§4 评测** —— 用户回「对」。
  **把「混淆矩阵」拆成两张,并且第 2 张不叫混淆矩阵**:① 每类一张 2×2(TP/FP/FN/TN),
  是每类 P/R/F1 的来源;② 一张 17×17 的**误判流向矩阵**(行=真实标签,列=预测标签,
  格=本该是 i 却被判成 j)—— 它才看得出 `运费↔物流`、`退换货↔保修维修` 这类近邻混淆,
  正是三条边界的验收集。**不叫它混淆矩阵**的理由:本仓吃过「名字与语义不符」的亏
  (`agent_steps`),多标签没有唯一预测类,直接画 17×17 是张人人能画、谁也读不懂的图。
  **小样本类标 `†`**:support<15 的行标 `†`,表头写「该行 F1 不成结论」。
  **分层报告打三遍**:全体 120 / 只看真实 80 / 只看合成 40 —— 合成与训练集同源会虚高,
  「只看真实 80」才是真机预期。
  **人工抽判错样本判的是「谁错了」而不是「模型对不对」**:模型错归模型账,标签错归数据账 ——
  多数是标签错就说明 F1 低不是模型的问题、该修的是数据。导出上界 60 条。
  产物 `report.md` + `report.json` + 两张矩阵 CSV,必跑出一条命令;**不参与任何随机**。
- **§5 旁路服务 + 批处理 + 表** —— 用户回「对」。
  **抓到第二个静默陷阱:标签顺序。** 模型第 5 个 logit 对应哪个类目靠的是**训练时标签列表的下标**;
  推理服务若自硬编码一份顺序而它与训练不一致,得到的是**一张完全错的分布图而每个组件都正常**
  (有输出、scores 在 0–1、写库成功、页面画得出来,没有任何东西报错)。
  防线:训练脚本把顺序写进产物 `models/topic-clf/labels.json`(从 `taxonomy.py` 生成),
  服务**读它不自己写** + 一条「服务顺序 == `taxonomy.LABELS` 逐位相同」的测试。
  `max_length` 同样进产物,不在服务里写死。
  批处理:**服务连不上就响亮失败、绝不写空标签**(NULL 行会让页面把「服务挂了」读成「没有主题」,
  同 ch09 那条 👎 回捞失败被读成「知识库缺这块」);**一个批次一个事务、整批原子**。
  表:**UNIQUE(`low_confidence_question_id`)** 是幂等的保证,并要写明**为什么这里能加而
  `review_queue` 刻意不能加**(那边是语义归并、这边是确定性重算,两件相反的事)。
  JSON 列一律 `JSON_TYPE()` 读。**池子只有 63 行的读数已当面记账**:图会很薄,
  不足以支撑「先补哪块知识」的决策,不能让它看起来像一份分布结论。
