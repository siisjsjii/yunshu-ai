按工作要求 3 用 Context7 查两个定死的选型,查出来一个**必须绕开的陷阱**:

- `langchain-mcp-adapters` 最新 **0.3.2**,它的 `Requires-Dist` 明写 **`mcp<2.0.0,>=1.24.0`**。
  而 PyPI 上 `mcp` 最新是 **2.2.0**,Context7 站点现在**整站都在讲 v2**
  (v2 把 `FastMCP` 改名成了 `mcp.server.mcpserver.MCPServer`,传输参数从构造函数挪到 `run()`)。
  ⇒ **照 Context7 的 v2 文档写 Server,会和 adapters 的依赖约束直接冲突**;
  即使强行 pin `mcp==2.2.0` 装上了,adapters 也是按 1.x 的 `ClientSession` 写的。
- 更坑的是:Context7 那个标着 v1 的 library id(`/websites/py_sdk_modelcontextprotocol_io`)
  **返回的也已经是 v2 内容**(文档站做过迁移,老 id 跟着走了)。
  ⇒ **文档在这一处不可信,改以锁定版本的轮子源码为准。** 直接读 `mcp-1.30.0` 的 wheel 确认:

  | 事实 | 证据 |
  |---|---|
  | 1.x 的入口是 `mcp.server.FastMCP`(不是 `MCPServer`) | `mcp/server/__init__.py`:`from .fastmcp import FastMCP` |
  | 传输参数在**构造函数**里(v1 语义) | `FastMCP(..., settings=Settings(...))`,含 `stateless_http` / `json_response` / `streamable_http_path` |
  | `mcp.streamable_http_app() -> Starlette`(路由 `/mcp`) | `mcp/server/fastmcp/server.py` |
  | `mcp.run(transport="streamable-http")` | 同上,`TRANSPORTS = Literal["stdio","sse","streamable-http"]` |
  | **`mcp.list_tools()` / `mcp.call_tool()` 是纯内存方法** | 同上 —— 单测可以**不起服务、不走 HTTP** 直接验工具注册 |

  最后一条对本项目特别值钱:**单测全程不联网**是硬规矩,而它让 MCP Server 的
  工具注册与入参校验可以在进程内单测,不必把 HTTP 拉进单测。

**翻车与返工**

1. **用户那一问逼出了一处「要求是空话」的地方。** 我原本打算原样沿用重试白名单,
   去读 `executor.py` 才发现:**现在唯一真的会重试的故障是超时** ——
   `ToolNotFound` / `ValidationError` 立即 `break`,`SQLAlchemyError` 直接上抛。
   于是要求 4 那句「重试只给网络抖动这类暂时性故障」**是空的**:
   连接被拒 / 传输中断走通用 `except Exception` → 502,**一次都不重试**。
   ⇒ 已写进 spec §6.3:MCP 传输类故障纳入可重试,数据库故障仍不重试。

2. **spec 自审抓到一处真矛盾(已改)。** 我初稿写的是
   `execute_tool(approved=True/False)` —— **布尔表达不了三态**。
   「**没问过**」与「**问过、用户说不**」用同一个值表达的话,
   取消路径会**再拿到一次 `confirmation_required`**,于是取消永远不落「权限拒绝」,
   **验收 5 直接落空**,而实现看起来完全正常(`confirmation_required` 是合法取值)。
   ⇒ 改成三态 `write_decision: "pending" | "approved" | "denied"`,并在 §5.3 把
   「为什么布尔不够用」写下来。

3. **另一处自审订正**:§6.5 初稿写了个含糊的 `format_result(spec, raw)`,
   读起来像「引擎里有个函数把要求 4 的三件事全干了」。实际上**三件事落在三个不同的地方**
   (内置的挑字段与枚举翻转在**工具自身**,MCP 的才过引擎),已改成一张表如实写清。
