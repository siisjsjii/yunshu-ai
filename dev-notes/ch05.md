### 澄清与选型结论

**三个澄清问题(逐个问,均已答复):**

1. **checkpointer 与 MySQL 的关系** → 选 **InMemorySaver,MySQL 仍是权威**。图状态
   (意图/检索结果/中间步骤)只在单次请求内贯穿;跨轮对话历史仍走 `load_history` 读
   MySQL、流完 `append_turn` 落库。不产生第二份真相。
2. **手写 Agent 循环的处置** → 选 **先手写跑通,再用 LangGraph 重构时删掉手写版**。
   手写版是中间产物,不是交付物;过程与运行证据留 dev-notes。
3. **置信度闸判据** → 选 **纯检索分数阈值,零额外模型调用**。顺带把 ch04 在
   `stream_turn` 里「Agent 答完后再自评」那一步拿掉 —— 正是用户说的「答完再判就晚了」。

**两个选型点(用户「开干吧」批准 A+A):**

- **主力 Agent = 手写 agent 节点 + 条件边**(不用 `ToolNode`/`create_react_agent`)。
  理由:工具执行必须走 `app/tools/executor.py`,它承载 CLAUDE.md 点名的错误语义
  (基础设施故障必须抛 502、重试白名单、`create_ticket` 永不重试、10s 超时)。
  `ToolNode` 直接 `tool.ainvoke`,这些语义全丢。
- **SSE 帧 = `stream_mode=["messages","custom"]`**。`messages` 取 token(按
  `metadata["langgraph_node"]` 只转最终回答节点);`custom` 用 `get_stream_writer()`
  在节点内发 `tool_call`/`tool_result`/`choices` 等结构化帧。

**API 核实(用户工作要求 3,已用 Context7 + 真机 import 双查):**

- Context7 `/langchain-ai/langgraph`:`StateGraph` / `add_conditional_edges` /
  `compile(checkpointer=...)` / `config={"configurable":{"thread_id":...}}` 用法确认。
- 真机 `langgraph 1.2.11` import 全通:`StateGraph`、`START`/`END`、`InMemorySaver`、
  `ToolNode`/`tools_condition`(存在但**不采用**);`astream` 支持
  `stream_mode`;`StreamMode` 取值 `('values','updates','checkpoints','tasks','debug','messages','custom')`;
  `langgraph.config.get_stream_writer` 存在。
