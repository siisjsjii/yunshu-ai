### ④ 翻车与返工

**写计划前的真机验证否掉了 spec 的两处设计**(已记 spec §12):

1. **`stream_mode="messages"` 弃用**。真机探针:`messages` 模式只从真 LangChain
   Runnable 出流,普通对象替身**什么都不产出**;而 `GenericFakeChatModel.bind_tools`
   直接抛 `NotImplementedError` —— 意味着 ReAct 节点在单测里根本没法用该模式。
   改为**只用 `custom`**:token 也由 `agent` 节点自己发。收益是**所有帧只有一条
   发出路径**。
2. **`get_stream_writer()` 在图外抛 `RuntimeError`**(`Called get_config outside of
   a runnable context`)。新增 `app/agent/emit.py:make_emitter()` 适配层。

**计划自检(三查:spec 覆盖 / 占位符 / 类型一致性)又抓到 7 处**,均在写入计划时修掉:

1. **`emit` 的求值时机是致命的**。初稿把 `make_emitter()` 写成「进去就取一次
   `get_stream_writer()`」。而 `make_emitter()` 是在**端点里**调的 —— 那时图还没跑,
   上下文里没有 writer,必然走到 `RuntimeError` 分支 → 永远 no-op → **前端一帧都
   收不到**,而所有单测仍然全绿(单测把 collector 直接注入节点,根本不经过这里)。
   改成**每次发帧时现取**;并新增 `test_emitter_sends_frames_through_astream_custom_mode`
   在真实的 `graph.astream(stream_mode="custom")` 下断言帧真的到了消费端、
   且 collector **没被碰过**(碰过就说明没拿到 writer)。
2. **三个固定话术出口不发 `token` 帧**。前端是「累积 token 画气泡」的;只写
   `state["reply"]` 的结果是后端有话、**前端空白** —— 验收 4 会直接失败,而单测
   断言 `out["reply"]` 全绿。改为三个工厂都带 `emit` 并各发 `token` 帧。
   (这处是「假绿测试」的教科书案例:断言的层和用户看见的层不是同一层。)
3. **`trace` 没有出口**。验收 1「走了强制检索节点」与验收 5「ReAct 不止一步」
   原本只能靠服务端日志或 `citations` 这类替代信号。改为 `log_turn` 用**同一条
   emit 通道**发一帧 `trace`,端点把它折进 `done` 帧、不外推给前端。验收脚本因此
   机械可断言,而且**不需要引入第二个 stream_mode**(少一个流模式 = 少一处
   「帧会不会被缓冲住」的风险)。
4. **两条恒真断言**(`assert True` 结尾)——按本项目「假绿测试是头号风险」的规矩,
   留着比删掉更糟。改为断言**发给模型的真实入参**:`_BoundModel` 记录 messages,
   断言 system 在最前、历史经 `to_lc_messages` 转过、证据块并进了本轮 human 消息。
5. **一处名实不符**:`test_recoverable_tool_failure_is_fed_back_not_raised` 的名字说
   「回灌」,函数体却在断言 `pytest.raises`。改为
   `test_unknown_tool_error_propagates_as_infrastructure_error`。
6. **`_graph` 辅助里的 `rounds or [[...]]`** 会把显式传的 `[]` 换成默认脚本 ——
   而 `[]` 正是「碰模型就炸」探针的载荷(闲聊/兜底/投诉三条出口靠它证明零模型调用)。
   改为 `rounds if rounds is not None else [...]`。
7. **验收脚本里一行死代码**:`if grep -q ... || true; then :; fi`(恒真且什么都不做),
   删掉。
