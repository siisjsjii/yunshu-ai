### ② 关键产出

- **目标流程图**:`asserts/ch06workflow.png`(已读,见 spec §3)
- **设计定稿**:`docs/superpowers/specs/2026-09-20-ecommerce-cs-ch06-intent-router-design.md`
- **四条实测事实**(先查文档、再实测,**没有一条是推的**):

  | # | 事实 | 影响 |
  |---|---|---|
  | F1 | `astream(stream_mode="custom")` **把 interrupt 整个吞掉** | 端点必须改 `["custom","updates"]`,否则订单卡片永不出现 |
  | F2 | interrupt 从 `updates` 浮出:`{'__interrupt__': (Interrupt(...),)}` | 端点认这个键并转帧 |
  | F3 | resume 时**节点从头重跑** | `refund_pick_order` 里 interrupt 之外不干任何事 |
  | F4 | 每请求重 compile + 同 checkpointer **能 resume**;**pending 时改发普通消息 → 从 START 重开、旧挂起丢弃** | 每请求建图可行;「不理卡片直接问别的」是安全路径 |

- **一个图上没有、验收 4 却绕不开的缺口**:系统里**没有 orders 表**,
  订单是 `hashlib` 按号码现算的 —— 订单选择器**没有候选来源**。
  用户拍板:**加一个「最近订单」能力**(扫会话历史 + 会话固定演示集),
  并要求代码里**如实注明是演示数据,不是真实用户订单**。

- **Context7 查了什么**:LangGraph `interrupt()` / `Command(resume=...)` 的语义与
  checkpointer 要求;并确认本机装的 **1.2.11** 里 `astream` / `stream_events` /
  `Command(resume=)` 都存在(文档示例用的是 `stream_events(version="v3")`,
  与我们端点的 `astream` **不是同一个 API** —— 所以行为以本机实测为准)。

### ③ 被拒绝 / 被纠偏了什么

- **用户否掉了三个替代方案**(都是我在提问里列出来的):
  「不用 interrupt、当成新一轮」被否 —— 要的就是**图中间真暂停**;
  「复用 tickets 表」被否 —— 要**结构化字段**;
  「固定演示订单号写死」被否 —— 要一个**能力**而不是散落的常量。
- **我自己否掉了「让用户手输订单号」**:那最诚实,但不是用户要的可点选卡片。

### ④ 翻车与返工

- **差点把 API 用错**:Context7 给的示例清一色是 `stream_events(version="v3")`,
  而我们端点在用 `astream(stream_mode="custom")`。**两个 API 的 interrupt 行为不同** ——
  照文档示例写会与现有代码对不上。处置:**到本机写最小图实测**,
  于是拿到 F1(只有 custom 会把 interrupt 吞掉)。**这条如果没实测,
  订单卡片会「永远不出现」且不报错** —— 正是本项目最怕的静默故障。
- **`/tmp` 陷阱复发**(Git Bash 的 `/tmp` 与 Windows 的 `/tmp` 不是同一个目录)。
  ch05 已经栽过一次,这次直接改用**仓库内相对路径**写探针,没再中招。

**自检三查(计划末尾有记录)**:

- 占位符:无 TBD;两处「由实现者定」都附了**必须满足的可测约束**,不是「自行发挥」;

**写计划时发现、必须写进计划的两条既有约束**(否则实现者会踩):
1. **`resolve_references` 还兼任「每轮重置」** —— checkpointer 是进程级单例、
   thread_id=session_id,不清零会把上一轮的 `gate_passed`/`agent_steps` 报成本轮的,
   **而且一路静默**。给它加消解时**必须保住这个职责**,并补上 `order_no` 等新通道。
2. **T1 的订单号正则 `\b\d{4,32}\b` 有假绿风险**(会匹配金额、日期)。
   计划里明写:只断「历史里有个号码」是**必要但不充分**,
   实现者须补**含金额干扰**的用例。
