## 阶段 1:brainstorm 勘察 + 澄清提问

**分类**:architectural(新子系统:可观测接入 + 三段式飞轮 + 两张新表 + 一条新的图出口)。
走完整路径。

**本轮勘察挖出来的、与需求描述不符的事实(四条,都当场告诉了用户)**

1. **`.env` 里配的是 Langfuse Cloud 美国区**,不是需求技术栈写的「自部署,链路数据不出自家服务器」。
   实测 `GET /api/public/ready` → `version: 4.41.0`。→ 用户拍板:**用云端**。
2. **需求里「生成阶段模型自评:ch04 已经在落池,确认接进飞轮即可」—— 半句是错的。**
   `app/kb/assess.py` 的 `assess_sufficiency` **自 ch05 起生产调用方为零**(它自己的
   docstring 就写着这件事)。今天在线的只有事前置信度闸那一行阈值比较。
   ⇒ 「生成阶段自评」是本章**要新建**的东西,不是「确认接上」。
3. **`Faithfulness` 全仓不存在。** ch04 的 `scripts/run_eval.py` 只有检索段五个指标。
   → 用户裁定:那个词指的是**置信度池那套机制**,不是评分指标 ⇒ 不做生成段评估。
4. **👎 要存的「当轮召回片段」没有现成来源。** 每轮的 `intent` 与 `evidence`
   **都没有持久化**(`log_turn` 只写日志行、发不外推的 `trace` 帧、落 messages)。

**被拒绝 / 被我改掉的方案**
- 我第一版设计提的是「`useful` 与作答同一次调用 ⇒ **这一步不能再逐字流式**,改成返回后按小段补发 token 帧」。
  **用户否掉了**,给出解法:**字段顺序控制** —— `useful` 放最前、`answer` 放最后,
  配一个增量 JSON 解析器边收边解析,`useful=true` 就放行并把 `answer` 的 token 直接透传,
  `useful=false` 就早停止损。**流式保住了。**

**翻车与返工**

- **我的探针第一版是假绿,而且是被我自己抓到的。** 我写了个脚本测
  「`bind_tools` + `response_format` 能不能同时用」,结果 `kwargs={}` 那两个分支
  **压根没把 `response_format` 挂上去** —— 测的是**裸 `bind_tools`**,输出看起来
  完全正常(模型乖乖吐了合法 JSON),差点被我当成人证。
  **这是本仓编目过的「验证装置自己产假绿」,这次又中了。**
  重写后强制每个变体把自己实际挂上了什么打出来。

- **第二版探针的结论句也是错的。** 我看到 `strict=True + 要求调工具` 返回 400,
  就下了「strict 路径调工具不通」的结论 —— 而那条 400 的原文是
  `Prompt must contain the word 'json' in some form`,**成因是我那条提示词里没有
  `JSON` 字样**(本仓 ch01 起就有的硬约束,我在同一个坑里第二次栽)。
  真结论是**未验**,不是「不通」。已写进 spec §15.1 订正。

- **Context7 这次不是「文档过期」而是「服务不可用」**:`WebFetch` 对 `langfuse.com`
  返回「Unable to verify if domain is safe to fetch」。改用 `curl` 直取成功。
  ⇒ 与本仓 ch08 那条「以轮子源码为准」并列的新形态:**取不到文档时不要凭记忆写,
  换通道取,取不到就把该条标成「未验」并留给冒烟。**

**探针实测结论(全部来自 `.superpowers/probe_ch09_json.py`,模型 `deepseek-flash`)**

| 组合 | 结果 |
|---|---|
| `response_format=json_object` + **不绑 tools** | ✅ 通,**原始 JSON 文本增量**,字段顺序就是提示词要的那个 |
| `bind_tools`(非 strict)+ `response_format` | ❌ 客户端 `ValueError: only strict function tools can be auto-parsed` |
| `bind_tools(strict=True)` + `response_format`,作答 | ⚠️ 通 |
| `bind_tools(strict=True)` + `response_format`,要调工具 | ❌ 400「提示词里要有 JSON」—— **未验,不是不通** |

根因读到了源码级:`.venv/.../langchain_openai/chat_models/base.py:2085-2097`,
只要 payload 里有 `response_format` 就 `payload.pop("stream")` 并改走
`root_async_client.beta.chat.completions.stream(...)`,而那条路径只接受 strict 工具。
