== 局限(「通过」不等于这些也被验过)—— 如实列在这里,不许读成全绿 ==
  * **① 那个 F1 是在「预标标签」上测的,不是在人工标注的黄金集上**:120 行里只有
    12 行带人工复核痕迹(用户 2026-09-26 拍板跳过测试集人工复核)。**逐类的 F1
    一条都不能当结论引用**(14/17 类带 †);能引用的只有全体/分层那几个汇总数,
    而 §8.4 指定的权威列是「只看真实 80」(那一列上 16/17 类带 †)。
    根因是**真实语料按类稀薄**(尺码 4 / 发票 14)—— 解救办法是补真实语料,
    不是调阈值、也不是把测试集做大(做大只改善合并列)。
  * **① 不覆盖「预标自己错了多少」**:**模型错 还是 标签错**要人看
    `evals/topic/misjudged.csv`(判错 39 条):若多数是标签错,该修的是数据不是训练。
    本脚本**不预判**这一点(§8.5 那份 CSV 的全部价值就是由人来做这个区分)。
  * **① 的「合计 = 输入 − 不可信靶子」依赖 `evals/topic/prelabeled.jsonl`,
    而它刻意不入库** ⇒ 全新 clone 上那一条报**「未复现」**(不是通过)。
  * **① 不改阈值、更不重训**:报告里 `t=0.3` 那一行只是冻结测试集上的无偏读数
    (测试集没参与任何选择),本轮采用的仍是产物里的 0.5。
  * **① 的「入库报告 == 本次运行」是一条硬断言**:它把验收与**当前这份权重**绑在
    一起 —— 换了权重而没重生成报告 ⇒ 本节红。那是「报告落后了」,不是产品坏了。
  * **② 写的是共享表**:池子今天已全部归过类 ⇒ 这一轮 `--limit 20` 是**覆盖写**
    (upsert 幂等),本脚本**没有**断言「本次新增了几行」(那要另造一条新池子行)。
  * **② 只验接口,不验页面**:分布页(admin.html 的标签页)是 Vibe Coding 的产物,
    「图有没有画对」本脚本看不到 —— 它只保证**接口那几个数的来源是对的**。
  * **② 的「不同问题数」是题面(未清洗)的不同数**:`clean()` 是 Python 侧的唯一
    实现,SQL 里那一次展开**没有**用清洗后的文本。
  * **③ 判的是「≥2 个类目」,不判具体是哪两个**:三个探针命中的类目**只打出来入账**。
    换一份权重它们可能合理地变 ⇒ 把具体类目写进判词会得到一条随训练摆动的断言。
  * **③ 走的是 `/predict`,不是对话链路** ⇒ 「用户说话之后分类器用没用上」不在这里验
    (主链路零调用分类器是 §9.4 的设计,由两条**源码扫描**测试守着)。
  * **错别字鲁棒性没有任何测试覆盖**(spec §13 第 6 条):保留 + 注入错别字是设计
    选择,而本脚本这三个探针**一个错别字都没有**。这是本章的已知盲区,不许写成「已解决」。
  * **承重的是 1 句**。另外 2 句是读数(不进判词)⇒ 「承重句过了」**不等于**
    「转人工稳定」,后者要看上面那几个数(3 句里调了几次、全过几次、报了几次工号)。
  * **第 ② 层失败的成因是结构性的,不是本脚本能修的东西**:转人工走主力 Agent
    意味着「发生不发生」取决于模型记不记得调工具,而模型只被要求决定**意图标签**。
    这是 ch06「模型只决定标签、不决定走向」的唯一一处例外(spec §11.3/§13.5),
    **没有结构保证,只有这个比例**。
  * **③ 的口径是「工号**或**等待/排队」(spec 的字面),它证明的是「结果被转述了」**;
    「模型报不报工号」是**另一个**读数,已单列(报出工号 / 只给等待),**没有合成一个数**。
  * **「投诉 vs 转人工」的边界不在本脚本覆盖内**:那两条边界负例在
    `evals/intent_cases.jsonl` 上由 `scripts/run_intent_eval.py` 测(打网络、不进验收)。
  * **「转人工之后会话有没有留痕」不在覆盖内**:`transfer_to_human` **刻意不落库**
    (不加 session 依赖)⇒ 转人工这一轮**没有自己的业务行**(`conversations.status`
    只有建工单那条路会写,而用户没有要工单)。这轮唯一的痕是**执行器为这次调用
    落的 `tool_audit_logs` 行**(`status=success`)—— 它是痕,但不是业务留痕,
    而本脚本**不断那张表**。
  * **「工号是不是真的」不在覆盖内**:②b 断的是那次调用的 `tool_result` 是 `ok:true`
    (⇒ 编号来自工具、不是模型编的),但**没有**核对回复里那个 `A###` 与
    `tool_result` 里的 `agent_no` **是同一个**。模型理论上可以报出另一个合法的工号
    —— 概率极低、且今天没有任何证据,但**这一条确实没被断**。
  * **前端那个按钮不在覆盖内**:投诉出口的「转人工」按钮改走真实路径是 ch10-A
    的另一件任务(Vibe Coding),本节走的是**接口**,不点按钮。
